## 1. Phase 8.1 – Integration Audit

The integration audit examined the connection between the frontend, backend, XGBoost threat detection model, PPO reinforcement learning agent, defense simulation components and blockchain logging system.

The audit confirmed the following pipeline:

1. Network traffic and input features are processed.
2. XGBoost classifies the incoming traffic.
3. A 26-dimensional state is constructed for the PPO agent.
4. PPO selects a defense action.
5. The defense simulator processes the selected action.
6. Security events are recorded in the blockchain ledger.
7. Frontend components display the available system information.

Key findings:
- ThreatDetection is integrated with the defense analysis API.
- BlockchainLogs retrieves blockchain records.
- LiveMonitoring uses backend live-flow information.
- Dashboard and Reports contain static or mock data.
- Some frontend lint errors and error-handling limitations remain.

Result: PASS WITH CAVEATS.

## 6. Known Limitations

1. Only four controlled scenarios were tested end to end.
2. Defense actions are simulated and do not enforce actual operating-system firewall rules.
3. Blockchain storage is a local JSON hash-linked ledger, not a decentralized blockchain network.
4. PPO training convergence could not be verified because training logs were unavailable.
5. The PPO policy showed a MONITOR-dominated action distribution in the full environment evaluation.
6. Production state construction contains differences from training-environment state construction.
7. Some frontend pages still use mock or static data.
8. The tests do not establish production-level cybersecurity effectiveness.

## 7. Final Conclusion

Phase 8 validated the integration of the XGBoost threat detection model, PPO reinforcement learning agent, simulated defense mechanism and blockchain event logging component.

Four controlled scenarios—Benign, DDoS, PortScan and Web Attack - Brute Force—successfully passed through the end-to-end integration pipeline.

The isolated blockchain contained 25 valid blocks after testing. Independent verification confirmed that all hashes and previous-hash links were correct. The original project's blockchain remained unchanged at 21 blocks.

Therefore, the controlled integration testing phase was successfully completed, subject to the limitations documented in this report.
